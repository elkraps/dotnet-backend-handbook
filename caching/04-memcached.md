## Memcached

### Архитектура

Memcached — простой, быстрый, distributed in-memory key-value store. Обрабатывает запросы несколькими worker threads; сериализацию объектов обычно выполняет клиент. Данные хранятся только в RAM.

**Slab Allocator** — механизм управления памятью. Избегает фрагментации:

```
Память делится на slab classes:
  Class 1: chunks по 64 байта
  Class 2: chunks по 128 байт
  Class 3: chunks по 256 байт
  ...
  Class N: chunks по 1MB

Запись "hello" (5 байт) → идёт в Class 1 (64-байтный chunk)
Запись "большой JSON" (200 байт) → идёт в Class 3 (256-байтный chunk)

Chunk занят даже если данные меньше → внутренняя фрагментация
```

Плюс: выделение chunks уменьшает проблемы внешней фрагментации; геометрия slab classes в примере упрощена.
Минус: внутренняя фрагментация (chunk больше данных).

### Consistent Hashing для распределения ключей

Набор Memcached-серверов распределяет данные с помощью клиента: каждый сервер сам по себе не управляет общим кластером. Простое распределение выглядит так:

```
servers = [server1:11211, server2:11211, server3:11211]
server = servers[hash(key) % len(servers)]
```

**Проблема:** при добавлении/удалении сервера большинство ключей переходит на другие серверы (cache flood).

**Consistent Hashing:** виртуальное кольцо, ключ идёт на ближайший сервер по кольцу. При изменении состава серверов при добавлении узла перемещается примерно `1/(N+1)` ключей при равномерном распределении; результат зависит от виртуальных узлов и весов.

### Ограничения Memcached

- Только строки (нет структур данных)
- Нет персистентности — перезапуск = потеря данных
- Нет репликации (встроенной)
- Нет Pub/Sub
- Нет атомарных операций на структурах
- Типичный лимит item: 1 MiB по умолчанию, настраивается
- Максимальный размер ключа: 250 байт

## Redis vs Memcached

| Критерий | Redis | Memcached |
|---------|-------|-----------|
| Структуры данных | String, List, Set, ZSet, Hash, Stream, HLL, Bitmap | Только String |
| Персистентность | RDB + AOF | Нет |
| Репликация | Master-Replica (встроена) | Нет |
| Cluster | Redis Cluster (встроен) | Только через клиент (consistent hashing) |
| Pub/Sub | Да (+ Streams) | Нет |
| Lua scripting | Да (атомарные скрипты) | Нет |
| Транзакции | MULTI/EXEC (optimistic) | Нет |
| Потоки | Однопоточный (I/O в 6+) | Многопоточный |
| Память | Зависит от типа, encoding и размера | Зависит от slab class и размера item |
| Размер значения | Для String обычно до 512 MB | Item обычно до 1 MiB, зависит от настройки |
| Применение | Универсальный | Простой кеш строк |

**Когда Memcached:** нужен простой распределённый кеш непрозрачных значений, и его модель соответствует инфраструктуре проекта.
**Когда Redis:** нужны серверные структуры данных, persistence, replication или атомарная обработка нескольких операций.

## Подводные камни

Предел размера значения зависит от конфигурации. Хеширование делает клиент; добавление сервера влияет на hit ratio и нагрузку на источник.
